Your first game, in about 15 minutes

You don't need to install anything or already know how to code. This page walks you through changing a real game, piece by piece, until it makes sense. By the end you'll understand enough to start changing things on your own.

1

Open the game editor

Go to the Make page. You'll see code on the left and a black rectangle (the canvas) on the right — that's where the game will appear.

2

Click Run

An orange square appears. Press the arrow keys — it moves. Press space — it changes color. That's a whole game, already written for you. Everything below is about understanding and changing it.

The four ideas behind every game

Every line of code in that box is doing one of four things. Once these click, you can read almost any short program.

variable

A labeled box for a value

SPEED = 200 means "make a box called SPEED and put 200 in it." Later, the code says box.x += SPEED * dt — it's using the number from the box.

if statement

Do this, only when...

if pressed[pg.K_LEFT]: means "only run the next line if the left arrow key is currently held down." Skip it otherwise.

loop

Repeat, forever

while running: repeats everything inside it, over and over — once per frame. That's the entire trick behind animation: draw, wait a tiny bit, draw again, ~60 times a second.

function

A named recipe

pg.draw.rect(...) is a function someone else already wrote — you just tell it what color and where, and it handles the actual drawing.

Now change it yourself

Make each change below, click Run again, and see what happened before moving to the next one. There's no way to break anything permanently — "Reset to example" on the Make page brings back the original any time.

1

Change the color

Find color = (232, 163, 61) near the top. Those three numbers are red, green, blue — each from 0 to 255. Change them to (255, 0, 0) and run it. The square is red now. Try (0, 255, 0), then whatever you want.

2

Make it faster

Find SPEED = 200. That's how many pixels it moves per second. Change it to 600 and run — the square zips around. Try 50 — it crawls.

3

Make it bigger

Find the line that creates the square: box = pg.Rect(WIDTH // 2 - 20, HEIGHT // 2 - 20, 40, 40). The last two numbers are its width and height. Change both 40s to 80 — bigger square. The - 20s are there to keep it centered; if you're curious, try changing the size without touching them and see what happens to where it starts.

4

Add a new key

Find this block: 

if e.type == pg.KEYDOWN and e.key == pg.K_SPACE:
    color = (79, 184, 166) if color != (79, 184, 166) else (232, 163, 61)

Copy those two lines, paste them right below, and change pg.K_SPACE to pg.K_r and the two colors to something new. Now both space and R change the color — to different colors.

Try these on your own

No answers given — this is where it starts being genuinely yours.

  • Make the square move twice as fast when you hold a key called pg.K_LSHIFT.
  • Make the timer text in the corner a different color.
  • Make the circle near the bottom follow the square's x position instead of staying still.
  • Make the square wrap around to the other side of the screen instead of stopping at the edge (hint: look at where box.x gets clamped with max/min).
  • Make pressing pg.K_UP and pg.K_DOWN also change the square's size instead of moving it.

When something goes wrong

Every beginner hits these. They're not a sign you did something badly wrong.

IndentationError

Python cares about spaces at the start of a line. If a line inside an if or while isn't lined up with the lines around it, fix the spacing so it matches.

SyntaxError: expected ':'

Lines that start a block — if, while, for, def — need a colon at the end. Easy to forget.

NameError: name 'x' is not defined

You used a variable before creating it, or misspelled its name. Check the spelling matches exactly, including capital letters.

Nothing seems to happen when you click Run

Check the text next to the Run button says "ready," not "loading" or "failed." The engine takes a couple seconds to load the first time.

Once this all feels comfortable

That's the point to start learning the topics that turn "a square that moves" into an actual game: collision detection (two things touching each other), game states (menu vs. playing vs. game over — the "Dodger" example on the Games page shows this), keeping score, and spawning multiple objects at once. Good next step: open the full Dodger example and try to explain to yourself what each part is doing before asking for help with it.
